# 项目高层步骤

第一部分：规划

充实本文档，为以下每个部分制定详细计划，将子步骤列为清单，供智能体（Agent）逐项勾选，并为每部分定义测试与成功标准。同时在 frontend 目录内创建 AGENTS.md，描述该目录已有的代码。确保用户检查并批准该计划。

第二部分：脚手架搭建

搭建 Docker 基础设施，在 backend/ 中用 FastAPI 搭建后端，并在 scripts/ 目录中编写启动与停止脚本。此阶段应托管示例静态 HTML，以确认"Hello World"示例能在本地运行，同时能发起一次 API 调用。

第三部分：接入前端

更新配置，使前端经静态构建后被托管，让整个应用在 / 路径展示演示看板。编写全面的单元测试与集成测试。

第四部分：加入模拟用户登录体验

更新应用，使首次访问 / 时需要使用虚拟凭据（"user"、"password"）登录才能看到看板，并支持登出。编写全面的测试。

第五部分：数据库建模

为看板设计数据库模式（Schema），以 JSON 形式保存。在 docs/ 中记录数据库方案并获得用户确认。

第六部分：后端

添加 API 路由，使后端能够读取并修改指定用户的看板；通过后端单元测试充分验证。若数据库不存在应自动创建。

第七部分：前端 + 后端

让前端真正调用后端 API，使应用成为具备持久化能力的看板。进行非常充分的测试。

第八部分：AI 接入

让后端能够通过 OpenRouter 发起 AI 调用。用简单的"2+2"测试验证连通性，确保 AI 调用正常工作。

第九部分：扩展后端调用，使其在调用 AI 时始终携带看板的 JSON 数据、用户的问题（以及对话历史）。AI 应以 Structured Outputs（结构化输出）返回对用户的回复，以及可选的看板更新操作。进行充分测试。

第十部分：在 UI 中添加一个精美的侧边栏组件，支持完整的 AI 聊天，并允许大语言模型（由其自行判断）基于 Structured Outputs 更新看板。若 AI 更新了看板，UI 应自动刷新。
